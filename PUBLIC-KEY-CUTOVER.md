approveRefund and denyRefund. `CLEANSTREAM_ACCOUNT_PUBLISHABLE_KEY_NAME` independently
selects for delete-account. Names come only from trusted server env, never requests.

nonempty `sb_publishable_` opaque-token shape. A shaped value still needs gateway
acceptance. No secret dictionary or service key is used by these callers.

name, missing own entry, malformed dictionary or wrong key kind/value fails closed.
Named mode never falls back to legacy/default, including after HTTP rejection.

selected key and captured bearer. No automatic mutation retry was introduced.

value, while legacy credentials remain authorized. Alternatively restore prior
wrappers/initialization with matching helper imports. Never restore compromised
keys or replay business actions. No provisioning/configuration/deployment here.

Public keys identify the application, not staff/customer authority. User bearer,
auth.getUser, caller RPCs, SQL/MFA/location checks and no-hard-delete contract remain.
No privileged promotion or verify_jwt change. Frontend ANON_KEY names need no churn.
